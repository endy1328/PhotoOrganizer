# PhotoOrganizer

## Git 추적 범위

소스 브랜치 `20261012`는 현재 `1.0.1.17 (2026-10-12)`까지의 소스·테스트·개발 문서·빌드 설정을 포함한다. `.gitignore`는 버전별 build/dist, Python 캐시와 환경, 로그, sessions/실행 저널, 작업 저장 파일, 개인 설정, 테스트 임시 폴더와 루트 GUI 검증 캡처를 제외한다. 제외 파일은 PC에서 삭제하지 않고 Git 추적만 제거한다. `PhotoOrganizer.spec`, `config.toml.sample`, README/AGENT/TASKS와 docs/tests/scripts는 추적한다. 공유 `.agents/skills`와 LICENSE·`skills-lock.json`은 유지하고 중복된 로컬 `.claude`/`.windsurf` 설치는 제외한다. 이미 생성된 커밋 이력은 재작성하지 않는다.

## 실행 확인과 진행 상세

`1.0.1.17 (2026-10-12)`는 실행 전에 선택된 사진·영상 수, 처리 방식, 사진 동시 처리 수, 영상 인코더와 예상시간 범위를 표시하고 `진행하시겠습니까?`를 확인한다. 취소하면 실행 checkpoint나 변환을 시작하지 않는다. 미리보기가 없거나 설정이 바뀌면 준비를 먼저 한다. 이어서 실행·재시도는 기존 복구 계획 검토 후 실행 가능한 항목의 예상시간을 확인한다.

작업 중에는 완료/전체 수, 경과시간, 예상 남은 시간과 현재 파일명을 표시한다. `진행 상세` 버튼 또는 `보기 > 실행 진행`으로 표시 전용 도킹 패널을 연다. 현재 처리 파일별 단계·경과와 최근50개 완료/실패를 보여주며 전체 완료·오류 집계는 최근 목록 제한과 무관하게 보존한다. 패널은 기본 숨김이고 좌우하단 도킹·분리·크기 조절·닫기·다시 열기를 지원한다. 닫기는 작업을 중단하지 않으며 전체 결과는 기존 실행 결과 탭에서 확인한다. 배치는 기존 화면 선호에 저장하고 기본 패널 배치 복원에 포함한다.

예상시간은 기존 크기·영상 길이·해상도·출력 설정을 활용하는 참고 범위다. 예상 계산을 위해 미디어를 추가로 읽거나 GPU/영상 probe를 하지 않는다. 자료가 부족하면 넓은 초기 범위를 사용하고 실행 중 완료 파일의 실제 속도로 보정한다. 첫 파일 처리 중에는 경과만큼 초기 잔여 시간을 줄이고 초과하면 초과 안내를 표시한다. 일시정지 대기는 보정에서 제외한다. 오류 없이 전체 완료한 실행만 실행 폴더의 `execution_estimates.json`에 품질/출력폭/인코더별 보정 비율로 저장하며 미디어 경로나 작업ID는 기록하지 않는다. HDD 동시 읽기·쓰기, GPU 상태와 다른 작업에 따라 실제 시간은 범위를 벗어날 수 있다.

최종 회귀567개 중565개 통과/Windows 링크 권한2개 skip. 한국어 작은 창/150%·200% 배율, 도킹 복원 및 EXE 버전·수정날짜와 내장12개 모듈을 확인했다. 실제 원격 환경에서 배포 EXE의 수동 조작은 별도 확인 대상이다.

## 작업 중 조회와 현재 파일

`1.0.1.16 (2026-10-12)`부터 미리보기·실행·이어서 실행 중에도 목록 선택/스크롤/탭 전환과 이미지 프리뷰·상세·메타정보·도킹/표시 설정을 사용할 수 있다. 파일명 편집, 모델 선택, 경로/모드 변경, 새 작업/열기/저장, 휴대폰 복사와 삭제는 작업 중 잠근다. 삭제 리뷰의 체크도 잠근다.

환경설정 버튼은 작업 중에도 활성화된다. 비모달 조회 전용 창에 실제 제출한 작업 설정을 표시하며 변경/저장/초기화는 막는다. 작업 중에는 진행 중인 변환에 영향을 주지 않고 설정을 확인할 수 있다. 작업 후 다시 열면 기존 편집 규칙을 적용한다.

진행 영역에는 현재 처리 중인 원본 파일명과 메타정보 읽기/정리/출력 변환/원본 이동 마무리 단계를 표시한다. 병렬 사진은 함께 표시하고 전체 경로는 툴팁으로 제공한다. 완료율과 파일명 SEQ는 기존 계획을 유지한다. 무거운 선택 파일 조회는 별도 단일 읽기 스레드에서 수행하며 최신 선택과 파일 상태가 일치할 때만 화면에 적용한다. 아직 생성되지 않았거나 이동으로 사라진 파일은 안내로 표시한다. 작업 중 영상 조회는 기존 메타정보 캐시를 우선 사용하며 캐시가 없으면 시간 제한이 있는 ffprobe 조회를 사용한다. 무제한 native MediaInfo 보조 조회는 작업 중 새로 시작하지 않으며 실제 정리 엔진의 추출 정책은 유지한다.

최신 실행 파일은 `dist_v1.0.1.17/PhotoOrganizer.exe`다. 소스는 사용자가 요청한 `origin/20261012` 반영 대상이며 EXE/로그/작업 파일은 Git에서 제외한다. 아래 `origin/20260112` 스냅샷은 이전1.0.1.15 소스에 해당한다.

전체 회귀530개 중528개 통과/Windows 링크 권한2개 skip, 작은 창과150%·200% 배율 및 배포 EXE 버전/수정날짜·내장 모듈을 확인했다. 실제 원격 환경의 EXE 수동 조작은 별도 확인 대상이다. 작업 중 제한적으로 읽은 영상 메타정보는 전체 조회 캐시와 분리하여 작업 후 전체 조회를 다시 할 수 있다.

Git 배포 소스 스냅샷: 사용자 요청(2026-10-12)에 따른 `origin/20260112`, 버전 `1.0.1.15 (2026-10-11)`. 브랜치명은 사용자가 지정한 값을 그대로 사용한다. 소스·테스트·개발 문서·빌드 설정을 포함하며 로컬 작업 파일, Python 캐시와 빌드 산출물은 포함하지 않는다.

## 작은 화면과 원격 접속

`1.0.1.15 (2026-10-11)`는 이미지·상세 독립 도킹 패널과 FHD/원격1204×1032 및 작은 창에서 목록 공간을 우선하는 화면을 제공한다. 원본·대상 경로는 기본 화면에 두고 디바이스명/처리 방식은 추가 옵션에서 펼친다. 작업 메뉴에서 새 작업·열기·저장을 사용한다. 처리 버튼은 좁은 창에서도 접근할 수 있게 배치하고 출력 설정 요약은 한 줄 및 전체 툴팁으로 제공한다.

처리할 모델은 화살표로 펼쳐 선택하며 많은 모델은 제한된 높이 안에서 스크롤한다. 이미지 프리뷰와 상세 정보는 제목을 드래그하여 왼쪽·오른쪽·아래쪽에 붙이거나 별도 창으로 분리한다. 패널 경계를 드래그하면 크기가 바뀐다. 보기 메뉴에서 각각 표시하거나 숨기고 기본 배치로 복원할 수 있다. 기본 배치는 넓은 창에서 오른쪽, 좁은 창에서 아래쪽이며 사용자가 옮긴 배치는 창 크기 변경으로 덮어쓰지 않는다. 선택 항목 정보와 메타정보는 탭으로 전환한다. 원본/대상/새 파일명 클릭별 상세 기준, 새 파일명 편집, UNKNOWN 색상 및 실행 제어는 유지한다.

목록 헤더를 오른쪽 클릭하면 열 표시를 선택할 수 있고 드래그로 열 순서를 조절한다. 새 파일명은 항상 접근할 수 있게 유지한다. 창 위치/크기·열 순서/너비/표시·패널 배치/크기/표시 상태는 실행 폴더의 `view_preferences.json`에 별도로 저장하며 작업 설정과 실행 계획 서명에는 포함하지 않는다. 다른 화면에서 열면 현재 사용 가능한 영역 안으로 창을 복원한다.

## 변환 성능

`환경설정 > 변환 성능`에서 영상 인코더와 변환 속도, 사진 동시 변환 수를 선택한다. 새 작업 기본값은 자동/균형/사진2개다.

| 설정 | 선택과 동작 |
|---|---|
| 영상 인코더 | 자동: NVIDIA NVENC 실제 인코딩을 확인하여 선택하고 불가/변환 실패 시 CPU로 전환. CPU: libx264. GPU: NVIDIA NVENC 지정, 불가 시 오류. |
| 변환 속도 | 화질·압축 우선 / 균형 / 빠름. 영상은 slow/medium/fast(CPU), p7/p5/p3(GPU). 사진 빠름은 JPEG/PNG 저장 압축 비용을 줄인다. |
| 사진 동시 변환 | 1/2/4개. 사진의 정리·출력·완료 기록을 처리하며 영상은 동시에1개씩 처리한다. |

기존6단계 품질과 해상도/메타정보/촬영 시각/용량 제외 정책을 유지한다. CPU는 CRF, GPU는 CQ를 사용하며 같은 숫자가 같은 화질·파일 크기를 보장하지 않는다. GPU 인코딩이 항상 빠른 것은 아니며 실제 영상과 저장장치에 따라 다르다. 실제 선택 인코더 및 자동 전환 사유는 출력 결과와 실행 로그에 남긴다. AMD AMF/Intel QSV 및 GPU 디코딩/축소는 이번 버전 지원 범위에 포함하지 않는다.

SEQ와 최종 경로는 미리보기에서 확정한다. 변환 완료 순서가 달라도 날짜별 사진·영상·모델·UNKNOWN 공통 번호 및 결과 목록 순서는 유지한다. 실패/중단 시 번호를 다시 배정하지 않는다. 병렬 처리 중 일시정지/중단은 새 파일을 시작하지 않고 이미 시작한 파일들을 마친 뒤 적용한다. 구버전 저장 작업은 CPU/균형/사진1개로 복원하여 기존 계획을 유지한다. 작업 저장을 사용하지 않는 내부 legacy 실행 경로는 사진을 순차 처리한다.

강제 종료 뒤 작업을 열면 기존 실행 DB의 미완료 트랜잭션을 복구하고 확정된 완료 기록을 읽는다. 복원 조회만으로 원본이나 변환 파일을 변경하지 않는다.

미리보기·실행·이어서 실행·실패 재시도 중 `일시정지`와 `중단`을 사용할 수 있다. 현재 파일의 정리·모바일 출력·이동 원본 제거 및 완료 기록을 끝낸 뒤 다음 파일 전에 멈춘다. 긴 영상은 변환 완료까지 기다리며 요청 상태를 즉시 표시한다. 일시정지는 `재개`로 계속하고, 중단한 실행은 완료 결과와 기록을 보존하여 `이어서 실행`할 수 있다. 중단한 미리보기는 기존 결과를 유지하며 다시 미리보기해야 한다. 마지막 파일까지 완료했다면 정상 완료한다.

작업은 별도 스레드에서 처리하며 영상 메타정보 조회·변환·썸네일용 ffprobe/ffmpeg는 Windows 콘솔 창을 숨긴다. 작업 완료로 창을 앞으로 가져오지 않으며 작업 오류는 상태와 오류 목록에 표시한다. 작업 중 설정·파일명 편집·상세 조회·저장·창 종료는 잠근다. 상세: `docs/superpowers/specs/2026-10-11-pause-stop-background-design.md`.

미리보기에서 `원본 경로`를 클릭하면 원본, `대상 경로` 또는 `새 파일명`을 클릭하면 대상 파일의 썸네일과 메타정보를 하단에 표시한다. 상세 기준과 경로를 함께 표시하며 대상이 미생성/누락이면 파일 없음 상태와 빈 메타정보를 표시한다. 새 파일명 편집은 유지한다. 새 작업·작업 열기·재미리보기의 초기 기준은 원본이다.

PhotoOrganizer는 Source 경로 아래 여러 폴더에 흩어져 있는 사진과 영상 파일을 읽어, 메타데이터 또는 파일명 정보를 기준으로 Target 경로 아래 규칙적인 디렉토리 구조로 정리하는 Python + PySide6 데스크톱 프로그램이다.

## 현재 상태

- 현재 릴리스는 `1.0.1.17 (2026-10-12)`이며 실행 확인/예상시간/진행 도킹 패널을 제공한다. 작업 중 조회는 `1.0.1.16`, 도킹 패널은 `1.0.1.15`, 작은 화면 개편은 `1.0.1.14`, GPU·사진 병렬 변환은 `1.0.1.13`, 일시정지·중단 및 영상 창 숨김은 `1.0.1.12`, 클릭별 상세 정보는 `1.0.1.11`, 작업 복구·실패 재시도는 `1.0.1.10`, 작업 저장·열기는 `1.0.1.9`에 추가되었다.
- 실행 가능한 PyInstaller 산출물 `dist/PhotoOrganizer.exe`가 포함되어 있다.
- Source/Target 선택, 미리보기, 실행, 오류 확인, 삭제 리뷰 흐름을 사용할 수 있다.
- 설정은 `config.toml`, 로그는 `logs` 폴더에 저장된다.
- 영상 메타데이터 보강 빌드(2026-10-10)는 `dist_video_metadata/PhotoOrganizer.exe`다. 기존 배포본과 별도로 생성했으며 설정/로그는 해당 실행 폴더 기준이다. 전체 테스트 66개와 소스 GUI 오프스크린 검증을 통과했으며, 새 실행 파일의 실제 GUI 미리보기는 추가 확인 대상이다.
- 최신 4자리 버전 배포 경로는 `dist_v1.0.1.17/PhotoOrganizer.exe`다. 창 제목과 Windows 파일 속성에서 버전을 확인할 수 있다. 설정/로그/실행 기록은 해당 실행 폴더 기준이다.
- 버전은 기존 `major.major.minor.minor` 4자리 형식을 유지하며 작은 수정은 마지막 자리를 올린다. 수정날짜는 실행일이 아닌 릴리스에 기록된 날짜다. 중간 3자리 빌드 `1.0.1`은 이 릴리스로 대체한다.

## USB 휴대폰으로 복사

- Target의 정리/모바일 출력 생성 후 `모바일로 복사` 버튼을 누른다. 프로그램을 다시 열어 기존 Target의 출력 폴더도 복사할 수 있다.
- Windows에서 Android 휴대폰을 USB로 연결하고 잠금을 해제한 뒤 USB 사용 옵션을 `파일 전송`으로 선택한다. 충전 전용 케이블은 지원하지 않는다. iPhone/ADB/USB 디버깅은 지원 범위가 아니다.
- 기기를 선택하고 저장소 및 폴더를 더블클릭해 저장 위치를 선택한다. `새 폴더`로 저장 위치를 만들 수 있다.
- Target 전체의 `output_` 폴더를 검색한다. 기본은 전체 선택이며 파일 수/용량을 확인하고 일부 폴더만 선택할 수 있다. 같은 이름의 출력 폴더가 여러 경로에 있으면 합치지 않고 오류로 안내한다.
- 선택한 휴대폰 경로 바로 아래에 `output_YYYYMMDD_MODEL` 폴더를 그대로 생성한다. 모든 하위 폴더와 실제 파일을 복사하며 PC의 일반 정리 파일은 전송하지 않는다. 링크/정션과 `.photoorganizer_*` 및 `.tmp` 작업 파일은 제외한다.
- 휴대폰 기존 폴더는 재사용한다. `환경설정 > 휴대폰 복사 > 동일 이름 파일 처리`에서 **덮어쓰기(기본)**, 건너뛰기, 새 이름으로 복사를 선택한다. 기존 설정 파일에 항목이 없거나 잘못된 값이면 사용자 지정 기본값인 덮어쓰기를 적용한다.
- 덮어쓰기는 새 파일을 임시 이름으로 먼저 전송·확인하고 기존 파일을 백업 이름으로 보존한 뒤 교체한다. 최종 이름/크기 확인 뒤 해당 기존 백업 파일만 제거한다. 기기가 이름 변경을 지원하지 않으면 기존 파일을 먼저 삭제하는 방법으로 우회하지 않고 실패를 표시한다.
- 건너뛰기는 같은 폴더에 같은 이름의 파일이 있으면 내용/크기가 달라도 유지한다. 새 이름으로 복사는 확장자를 유지해 `사진_copy0001.jpg`부터 사용 가능한 이름을 찾아 두 파일을 모두 보존한다. 이름 비교는 대소문자를 구분하지 않으며 내용 중복 비교는 하지 않는다.
- 폴더/파일 형식 충돌이나 같은 이름의 여러 객체는 자동 교체하지 않는다. PC 원본과 휴대폰의 다른 파일/폴더는 삭제하지 않는다.
- 결과는 복사 완료/건너뜀/실패/취소/검증 미완료로 구분한다. 완료는 신규 파일 생성과 이름/크기 확인 기준이며 전체 내용 해시 검증은 아니다.
- 취소는 진행 중인 쓰기 청크 경계에서 요청한다. 덮어쓰기의 이름 교체를 시작한 뒤에는 교체/복구를 먼저 마무리한다. 연결 해제/시간 초과/검증 미완료 시 기기와 저장 위치를 다시 조회한 뒤 재시도한다. 바이트 단위 이어받기는 지원하지 않고 선택한 동일 이름 정책을 다시 적용한다. 검증 미완료 시 남은 임시/백업 파일 이름을 결과에 표시하므로 휴대폰에서 확인해야 한다.
- Windows 내장 PowerShell와 WPD COM을 이용하며 추가 Android 앱 설치나 USB 디버깅은 필요 없다. 정책상 PowerShell/C# 실행이 차단된 환경은 연결 도우미 오류를 표시한다.
- 전송 결과 로그는 실행 폴더의 `logs` 아래 JSONL로 보관하고 30일이 지난 로그를 정리한다. 같은 시각의 여러 작업 로그도 덮어쓰지 않는다.
- 1.0.1.1은 전체162개 테스트(161통과/링크 권한1skip), Windows C# 교체 상태 머신, 실제 연결 갤럭시의 읽기 전용 탐색/파일명 변경 지원 속성을 검증했다. 실제 휴대폰 쓰기/취소/케이블 분리 검증은 후속 확인 대상이다.

## 정리 규칙

- 사진의 촬영 일시 우선순위는 `EXIF DateTimeOriginal` > `DateTimeDigitized` > `DateTime` > 파일명 fallback 이다.
- 영상의 촬영 일시 우선순위는 메타데이터의 생성/촬영 시각 > 파일명 fallback 이다.
- 영상 메타 시각에 UTC 오프셋이나 `Z`가 포함되어 있으면, 정렬과 파일명 생성에는 실행 환경의 로컬 시간대로 변환한 값을 사용한다.
- 파일 시스템 시간은 촬영 일시 판단 기준으로 사용하지 않는다.
- 영상 파일에 모델명이 없으면 같은 디렉토리의 모델명/촬영 시각이 확인된 사진·영상에서 후보를 찾는다. 시간 범위는 환경설정의 `영상 모델명 보완 > 전후 시간 범위(±)`에서 분 단위로 설정한다(기본 5, 범위 0~1440, 0은 동일 시각만). 기존 설정 파일에는 기본값을 적용한다.
- 1차 범위 비교는 시간 차이가 가장 작은 후보를 사용하며, 동률 후보의 모델명이 서로 다르면 이 단계에서는 모델을 확정하지 않는다. 추론으로 모델명이 채워진 영상은 다른 영상의 후보로 재사용하지 않는다.
- 설정 범위 비교 후에도 영상 모델명이 미확인이면 같은 폴더의 앞뒤 사진을 시간 제한 없이 추가로 확인한다. 촬영 시각이 가장 가까운 이전/이후 사진 그룹의 모델이 모두 같을 때 사용한다. 한쪽에만 사진이 있으면 그쪽 모델을 사용하며, 사진이 없거나 앞뒤/동일 시각 그룹의 모델이 서로 다르면 UNKNOWN을 유지한다. 영상 후보에는 시간 제한 없는 추가 보완을 적용하지 않는다.
- 시간 제한 없는 보완은 `모델명 근거`에 `영상 모델명 앞뒤 사진 추론(시간 제한 없음)`으로, 하단 메타정보에는 사용한 사진 경로·시간 차이·시간 제한 없음을 표시한다. 환경설정의 분 값은 첫 번째 범위 비교에만 적용된다.
- 범위 비교와 앞뒤 사진 보완 후에도 모델명이 확정되지 않으면 `UNKNOWN`으로 처리한다.
- 영상 모델명 추론 실패 안내는 촬영 일시 없음, 같은 폴더의 유효한 사진/영상 없음, 설정 시간 범위의 후보 없음(가장 가까운 후보와의 초 차이), 가장 가까운 후보 모델 충돌을 구분한다.
- 미리보기의 `영상 모델 조회`는 직접 확인/지원 태그에서 모델명 미확인/영상 메타 조회 실패를 표시한다. `모델명 근거`는 최종 모델명을 얻은 출처다. 하단 메타정보에서 영상 원본 모델명, ffprobe/MediaInfo 각각의 조회 결과, 보완 후보 경로·시간 차이를 확인할 수 있다. 모델 태그 미확인은 안내이며 파일에 모든 모델 정보가 없다는 단정이 아니다. 일부 도구만 실패한 경우도 상세 조회 결과에 남긴다.
- 최종 모델명이 UNKNOWN인 미리보기 행 전체는 연한 빨간색 배경으로 표시한다. 모델이 확인되면 일반 배경을 사용한다. 파일명만 편집해도 원본 모델명 판정은 그대로이므로 UNKNOWN 배경을 유지할 수 있다.

## 미리보기 파일명 수정

- 미리보기의 `새 파일명`을 더블클릭하거나 F2로 수정한다. 복사/이동 및 모바일 출력 경로에 수정한 이름을 반영한다.
- 수정은 파일명에만 적용하며 분류 폴더, 추출된 모델명/출처, 원본 파일의 메타데이터는 유지한다. 확장자는 원본 포맷을 유지한다(대소문자 변경은 가능).
- 잘못된 문자, Windows 예약 이름, 너무 긴 이름, 기존 파일 및 다른 미리보기 출력과의 충돌은 수정 시 거절한다. 사용자 지정 출력은 기존 파일을 덮어쓰지 않는다. 실행 직전에 파일이 생긴 경우에도 오류로 처리한다.
- 사용자 지정 모바일 출력은 임시 파일로 생성 후 덮어쓰기 없이 게시한다. 사용자 지정 이동은 모바일 단계까지 성공한 뒤 원본 경로를 제거한다. 실패 시 원본은 남으며 이미 성공한 주 출력본이 함께 남을 수 있다.
- 실행 중/실행 완료 후에는 이름을 수정할 수 없다. 설정이 바뀌면 수정한 미리보기를 그대로 실행하지 않으며, 미리보기를 다시 만든 뒤 이름을 수정해야 한다. 새 미리보기를 만들면 이전 수동 편집은 초기화된다.

## 정리 정책 참고
- 영상 모델 태그는 대소문자를 구분하지 않고 `com.apple.quicktime.model`, `model`, `camera_model`, `device_model`, `recorded_hardware_model_name`을 확인한다. 컨테이너의 빈 값/UNKNOWN은 유효한 스트림 모델을 가리지 않는다. 제조사, Android 버전, 인코더 이름은 모델명으로 사용하지 않는다.
- ffprobe 출력은 바이트로 받은 뒤 UTF-8로 해석한다. 빈 출력/잘못된 JSON/비정상 종료는 경고에 기록하고 MediaInfo 및 파일명 fallback을 계속 적용한다. ffprobe 대기 제한은 파일당 60초다.
- 원본 영상에 모델명이 없다면 정확한 모델명을 직접 복원할 수 없다. 같은 기기로 촬영한 자료만 선택했다면 `디바이스명(선택)`으로 이번 작업 전체의 모델명을 지정할 수 있다.
- 이름 충돌 시 확장자, 용량, 실제 추출 메타데이터가 모두 같으면 기존 파일을 덮어쓴다.
- 일반 출력 파일의 확장자 표기는 소스 파일의 대소문자를 그대로 유지한다. 예를 들어 소스가 `.jpg`면 타겟도 `.jpg`, 소스가 `.JPG`면 타겟도 `.JPG`다.
- 같은 날짜 디렉토리 아래에는 `YYYYMMDD_모델명` 디렉토리를 한 단계 더 만든다.
- SEQ는 같은 날짜의 모든 모델명 디렉토리와 UNKNOWN 디렉토리가 공유한다. 촬영 일시 오름차순으로 `0001`부터 이어지며 모델명이 달라져도 초기화하지 않는다. 날짜가 달라지면 다시 `0001`부터 시작한다.
- 같은 날짜 기준으로 배정된 SEQ 파일명이 이미 존재하지만 덮어쓰기 조건이 맞지 않으면 번호를 건너뛰지 않고 `충돌`로 표시한다.
- 사진과 동영상은 정리 완료 후 같은 모델명 디렉토리 아래 `output_YYYYMMDD_모델명` 폴더에 모바일 출력본을 추가 생성할 수 있다.
- 사진 모바일 출력 대상은 `JPG/JPEG/PNG/HEIC`이며, 사진 기본값은 최대 가로 `3000`, JPEG 품질 `75`, 작은 원본은 원본 크기 유지 규칙을 사용한다.
- 동영상 모바일 출력은 `MP4(H.264/AAC)`로 생성하며, 기본값은 최대 가로 `1280`, 품질 `balanced`, 원본보다 작아질 때만 저장이다.
- 모바일 출력 단계에서 하나라도 실패하면 전체 실행을 실패로 처리한다.
- 모바일 출력 `JPG/JPEG`는 원본 EXIF와 ICC 프로파일이 있으면 함께 보존한다.
- 모바일 출력 `PNG`는 PNG 텍스트 메타데이터와 ICC 프로파일, 가능한 경우 EXIF를 함께 보존하고 압축 최적화 저장을 사용한다.
- 모바일 출력 `HEIC`는 현재 JPG로 저장하며, Pillow 디코더가 노출한 EXIF와 ICC 프로파일이 있으면 함께 보존한다.
- 기본 파일 처리 정책은 복사다. 사용자가 선택하면 이동도 지원한다.
- 삭제는 자동 수행하지 않고 실행 후 결과 목록을 확인한 뒤 휴지통 이동 방식으로 처리한다.
- 오류 파일은 건너뛰고 로그에 기록한다.

## 파일명 규칙

```text
YYYYMMDD_HHMMSS_CAMERA_MODEL_SEQ4.EXT
```

예시:

```text
20161008_010134_RX100M3_0001.JPG
```

모델명을 확정하지 못하면 `UNKNOWN`을 사용한다.

## 파일명 Fallback 패턴 우선순위

1. `YYYYMMDD_HHMMSS_MODEL`
2. `YYYYMMDD_HHMMSS`
3. `IMG_YYYYMMDD_HHMMSS`
4. `YYYY-MM-DD HH.MM.SS`
5. `YYYYMMDD`

이미 정리된 파일명처럼 `YYYYMMDD_HHMMSS_MODEL_SEQ4` 형태를 다시 읽을 때는 마지막 `SEQ4`를 모델명으로 보지 않고 제거한 뒤 모델명을 해석한다.

## UI에서 할 수 있는 일

- Source 경로 선택
- Target 경로 선택
- 디바이스명(선택) 입력
- 처리 모드 `copy` 또는 `move` 선택
- 버튼 줄 오른쪽 `환경설정` 버튼으로 모바일 출력 정책 관리
- 미리보기 실행
- 실제 실행
- 오류 목록 확인
- 복사 모드 실행 후 삭제 리뷰 항목 선택 및 휴지통 이동

미리보기에는 변경 전 경로, 변경 후 경로, 새 파일명, 일시 근거, 모델명 근거, 오류 예상이 표시된다.
미리보기에는 추가로 `신규 생성`, `덮어쓰기`, `충돌` 같은 처리 방식 예상도 함께 표시된다.
상단 `디바이스명(선택)` 입력에 값이 있으면, 메타데이터나 파일명에서 읽은 모델명 대신 그 값이 이번 작업 전체의 디바이스명으로 우선 적용된다.
상단 `디바이스명(선택)` 입력칸 아래에는 현재 override 활성 여부를 즉시 보여주는 안내 문구가 표시되어, 저장된 값이 남아 있는 상태를 바로 확인할 수 있다.
디바이스명과 모델명은 파일명 안전 문자만 정리하고, 사용자가 입력한 대소문자는 그대로 유지한다.
같은 기기인데 공백, 밑줄, 하이픈 유무만 다른 표기(`Galaxy Z Fold6`, `GalaxyZFold6`, `Galaxy_Z_Fold6`)는 같은 모델로 정규화해 하나의 모델 디렉토리와 같은 SEQ 흐름으로 묶는다. 이때 대표 표기는 `사용자 입력 > 사진 메타 > 영상 메타 > 파일명 fallback` 우선순위로 선택한다.
디바이스명을 수동 입력한 경우에도 SEQ는 같은 날짜의 모든 모델명/UNKNOWN 디렉토리가 공유하며 `0001`부터 촬영 일시 순서로 증가한다.
미리보기 직후 같은 입력값으로 `실행`하면, 실행은 방금 표시한 미리보기 결과를 그대로 사용해 실제 생성 경로와 일치하도록 유지한다.
미리보기, 실행 결과, 오류, 삭제 리뷰 표의 헤더는 모두 마우스로 가로 폭을 직접 조절할 수 있다.
표 셀 텍스트는 줄임표(`...`)로 생략하지 않되, 각 셀 영역 안에서만 그리도록 유지하고 가로 스크롤과 수동 컬럼 폭 조절을 통해 전체 문자열 기준으로 확인할 수 있다.
선택한 행의 전체 원본 경로, 대상 경로, 오류 경로, 삭제 대상 경로와 세부 내용은 표 아래 상세 영역에서 잘리지 않은 상태로 확인할 수 있다.
표 아래 상세 영역은 좌우 분할로 구성되어, 왼쪽에는 선택한 사진 파일의 축소 이미지 미리보기가 표시되고 오른쪽에는 `선택 항목 정보`와 `메타정보`가 상하 2단으로 표시된다.
메타정보 영역에는 미디어 종류, 확장자, 파일 크기, 원본 크기, 추출된 촬영/생성 일시, 추출된 모델명, 메타 추출 도구, 일시/모델명 출처와 사진/영상별 핵심 메타가 `항목 | 값` 형태로 표시된다.
영상 파일은 `ffmpeg`가 있을 때 썸네일 프레임 1장을 추출해 표시하고, 같은 도구를 사용해 모바일 출력용 `MP4(H.264/AAC)` 재인코딩도 수행한다. `ffmpeg`가 없거나 추출에 실패하면 썸네일은 placeholder를 표시하고, 동영상 모바일 출력은 실행 오류로 처리한다.
메인 화면에는 모바일 출력 요약 상태를 함께 표시하고, 하단 상세 영역에서는 사진/동영상 모두 모바일 출력 예정 경로와 실행 결과를 확인할 수 있다.
미리보기와 실행 중에는 현재 단계와 처리 건수가 상태 문구와 진행 바로 표시된다.
모바일 출력본을 다시 입력으로 사용하더라도 파일명 fallback이 `MODEL_SEQ4`를 모델명으로 오인하지 않도록 보정했다.
실행 결과 탭에는 모바일 출력 상태와 모바일 출력 경로도 함께 표시한다.
실행 결과 탭에서는 `원본` 컬럼을 클릭하면 원본 파일 기준 미리보기/메타정보를 보여주고, `대상` 컬럼을 클릭하면 실제 생성된 대상 파일 기준 미리보기/메타정보를 보여준다. `모바일 출력 경로`를 클릭하면 생성된 output 파일 기준 미리보기/메타정보를 보여준다.

## 실행 방법

### 1. 가장 쉬운 방법

아래 실행 파일을 직접 실행하면 된다.

```powershell
.\dist\PhotoOrganizer.exe
```

### 2. 소스코드로 실행

권장 순서는 아래와 같다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -U pip
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m photo_organizer.main
```

또는 루트 진입점 파일로 실행할 수 있다.

```powershell
.\.venv\Scripts\python.exe main.py
```

### 3. 수정 후 테스트할 때 권장 순서

개발 중에는 exe보다 소스 직접 실행을 기준으로 확인하는 편이 맞다. 권장 순서는 아래와 같다.

1. 단위 테스트 먼저 실행

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

2. 최신 소스를 직접 실행해서 UI와 기능 확인

```powershell
.\.venv\Scripts\python.exe -m photo_organizer.main
```

또는

```powershell
.\.venv\Scripts\python.exe main.py
```

3. 배포 확인이 필요할 때만 exe를 다시 빌드해서 실행

```powershell
.\.venv\Scripts\python.exe -m PyInstaller PhotoOrganizer.spec
.\dist\PhotoOrganizer.exe
```

기존 exe가 잠겨 있으면 대체 빌드를 사용한다.

```powershell
.\scripts\build_release.ps1
.\dist_release\PhotoOrganizer.exe
```

정리하면, 평소 수정 확인은 `.venv` 기반 소스 실행으로 하고, `dist\PhotoOrganizer.exe`는 최종 배포 확인 단계에서 보는 것이 맞다.

### 4. requirements 기반 설치

`requirements.txt`를 써서 설치하려면 아래처럼 진행한다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -U pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install -e .
```

### 5. 기존 exe가 잠겨 있을 때 대체 빌드

`dist\PhotoOrganizer.exe`가 실행 중이거나 잠겨 있어 덮어쓰기 빌드가 실패하면, 대체 출력 경로로 새 exe를 만들 수 있다.

```powershell
.\scripts\build_release.ps1
```

기본 출력은 아래 경로다.

```text
dist_release\PhotoOrganizer.exe
```

## 외부 의존성 메모

- 영상 메타데이터를 정확히 읽으려면 시스템에서 `ffprobe`를 사용할 수 있어야 한다.
- 영상 썸네일 미리보기를 쓰려면 시스템에서 `ffmpeg`를 사용할 수 있어야 한다.
- `ffprobe`가 없으면 영상 메타데이터 추출은 경고를 남기고, 가능하면 `pymediainfo`와 파일명 fallback으로 계속 진행한다.
- `ffmpeg`가 없으면 영상은 썸네일 대신 placeholder로 표시한다.
- Windows 한글 로캘에서도 `ffprobe` JSON 출력은 UTF-8 기준으로 읽도록 처리해, 실행 시 CP949 디코딩 오류가 나지 않도록 보정했다.

## 모바일 출력 파일 날짜 (1.0.1.2)

- 새로 생성한 output_ 사진/영상의 수정·접근 시각과 Windows 만든 날짜는 미리보기의 촬영 시각으로 설정한다. 메타데이터 우선, 없으면 파일명 fallback을 그대로 따른다. 파일 시스템 시간을 촬영 근거로 사용하지 않는다.
- 원본 파일과 기존 EXIF/영상 메타데이터 보존 정책은 유지한다. 수동 파일명에서도 원래 추출한 촬영 시각을 사용한다. SKIPPED 파일과 이전에 생성한 출력에는 날짜를 소급 변경하지 않는다.
- 이 정책은 PC 출력 파일에 적용한다. USB 전송 후 휴대폰 파일 시스템 날짜 보존은 이번 수정 범위에 포함하지 않는다.

## 미리보기에서 처리할 모델 선택 (1.0.1.3)

- 미리보기 탭의 파일 표 바로 위에서 모델별 체크박스로 이번 작업의 처리 대상을 선택한다. 모델명과 사진/영상 수를 가로로 표시하고 공간이 부족하면 줄바꿈한다. UNKNOWN도 선택할 수 있으며 처음에는 모두 선택한다.
- 선택 해제한 모델의 행은 회색과 `제외` 표시로 남는다. Target 복사/이동, output_ 생성, 실행 결과 및 삭제 리뷰에서는 제외된다. 이미 Target에 있는 파일은 삭제하지 않는다.
- 선택할 때마다 포함 파일을 기준으로 날짜별 SEQ와 대상 경로를 재계산한다. 사용자가 수정한 파일명은 유지하며, 선택 재계산에서 기존 파일 또는 다른 항목과 이름이 겹치면 충돌을 표시하고 해당 파일을 건너뛰어 오류로 기록한다. 체크 변경에서 메타데이터를 다시 읽거나 덮어쓰기 여부를 자동 판정하지 않는다. 일반 최초 미리보기의 기존 충돌 판정은 유지한다.
- 파일명 편집으로 충돌을 해소하면 선택 목록 전체의 충돌 상태도 다시 확인한다. 제외 행의 파일명은 먼저 모델을 다시 선택한 뒤 수정할 수 있다.
- 선택 전에 전체 Source의 모델 추론을 완료한다. 제외 모델의 사진도 추론 근거가 될 수 있고, 선택 변경으로 촬영 시각이나 추론 근거가 바뀌지 않는다.
- 선택은 현재 미리보기에서만 유지한다. 새 미리보기는 모두 선택으로 시작한다. 모델 선택 후 Source/Target/정리 설정이 바뀌면 재미리보기를 요구한다. 모든 모델을 해제하면 실행을 막는다. 실행 중과 실행 후에는 모델 체크를 잠근다.
- `모바일로 복사` 창은 Target에 이미 존재하는 output_ 폴더들을 계속 표시한다. 이번 미리보기의 모델 제외가 이전 출력 파일까지 숨기거나 삭제하지 않는다.

## DJI Action4 영상 모델명 보정 (1.0.1.4)

- `DJI_20240501113332_0053_D.MP4` 같은 DJI 파일명은 전용 패턴을 먼저 적용한다. 촬영 시각만 추출하며 순번 `0053`과 끝의 `D`를 모델명으로 사용하지 않는다.
- 명시 모델 태그를 우선 조회하고 없으면 실제 원본에서 확인된 encoder `DJI OsmoAction4`만 제한적으로 모델 정보로 인정한다. 모델명은 `DJI_OsmoAction4`로 표시한다. 키 대소문자와 값 공백 차이는 정규화한다.
- ffprobe 컨테이너/스트림과 MediaInfo 전체 트랙에서 명시 모델 태그가 encoder보다 우선한다. 제조사 이름, 일반 인코딩 프로그램, 확인되지 않은 DJI 기종으로 Action4를 추정하지 않는다.
- 기기를 확인하지 못하면 기존 모델 추론/UNKNOWN 정책을 따른다. DJI라는 파일명만으로 Action4를 지정하지 않는다. 촬영 시각은 영상 메타데이터 우선 정책을 유지한다.
- 기존 잘못 생성된 파일/폴더는 자동 변경하지 않는다. 새 EXE에서 원본 DJI 파일이 있는 Source로 미리보기를 다시 생성한다.

## 모델명 별칭 매핑 (1.0.1.5)

1. `환경설정 > 모델명 매핑`에서 추가를 누르고 원본 모델명과 사용할 별칭을 입력한다. 표를 직접 편집하고 선택 행을 삭제할 수 있다.
2. 적용 범위를 고른다. 기본 `새 파일명 + 분류 폴더`는 분류 폴더와 그 아래 output_ 폴더도 별칭을 사용한다. `새 파일명만`은 두 폴더를 원래 모델명으로 유지한다.
3. 확인 후 미리보기를 다시 생성한다. 모델 체크 목록에 원본→별칭을 표시하고 상세 정보에 추출 모델명/파일명 적용 모델명/분류 폴더 모델명을 함께 보여준다.

예: DJI_OsmoAction4 → Action4, 기본 범위이면 `20240501_Action4/20240501_113333_Action4_0001.MP4` 및 `output_20240501_Action4`가 생성된다. 파일명만 적용이면 폴더는 `20240501_DJI_OsmoAction4`와 `output_20240501_DJI_OsmoAction4`로 유지한다.

- 원본 메타데이터와 모델 추론은 변경하지 않는다. 매핑은 확정 모델의 출력 이름에만 한 번 적용한다. 매핑 원본은 기존 모델 그룹처럼 대소문자/공백/구분자 차이를 정규화해 비교하고 중복 등록은 거부한다.
- 여러 원본에 같은 별칭을 등록할 수 있다. 날짜별 공통 SEQ를 유지하며 모델 체크는 별칭이 같아도 원본별로 선택한다. UNKNOWN을 매핑해도 원래 미확인 상태와 행의 연한 빨간색 표시는 유지한다.
- 한글 별칭을 지원하고 내부 공백은 밑줄로 저장한다. 빈 값, 경로/제어문자, Windows 예약 이름, 끝의 점, 180 UTF-16 단위를 넘는 이름은 거부한다. 등록하지 않은 모델은 기존 이름을 사용한다. 기본값 복원은 매핑을 비우고 모두 적용 범위로 돌아간다.
- 설정은 기존 config.toml의 `[model_name_mappings]` 및 `[app].model_mapping_scope`에 저장한다. 이전 설정에는 빈 매핑/모두 적용 기본값을 적용한다. 저장 전 검증 후 같은 폴더의 임시 파일을 교체해 저장 실패 시 기존 설정을 보존한다.
- 매핑/범위 변경 후 기존 미리보기를 바로 실행할 수 없다. 같은 Source·Target에서 매핑 변경으로 재미리보기하면 직접 수정한 전체 파일명은 새 분류 폴더에 유지하며 충돌을 표시한다. 복원 검증 실패 시 기존 미리보기를 보존한다. 모델 선택 재계산에서도 직접 수정한 파일명은 유지한다.
- 기존 출력 파일/폴더와 휴대폰 자료는 자동 이름 변경하지 않는다. 설정 파일은 실행 폴더 기준이므로 새 EXE를 다른 폴더에서 실행하면 기존 설정을 가져와야 한다.

## 모바일 복사 동영상 용량 제한 (1.0.1.6)

환경설정의 **휴대폰 복사 → 용량이 큰 동영상 복사 제외**를 켜고 기준 용량을 MB로 입력합니다. 기본은 해제이며 입력 기본값은 500 MB입니다. 1 MB는 1,000,000 바이트이고 기준과 같은 크기도 제외합니다.

판정 대상은 실제 전송할 `output_` 영상(MP4/MOV/M4V/AVI/MKV/WMV)입니다. 원본 영상 크기나 사진에는 적용하지 않으며 PC 파일을 변경하지 않습니다. 복사 창에 전송 파일 수·용량과 제외 수를 표시하고, 결과·로그에는 용량 제한 제외 이유를 남깁니다. 제외한 영상은 휴대폰의 기존 같은 이름 파일도 유지합니다. 제한 활성 시 전송할 파일이 없는 폴더는 새로 생성하지 않습니다.

설정은 `config.toml`의 `phone_video_limit_enabled = false`, `phone_video_limit_mb = 500`에 저장됩니다. 새 EXE 폴더에서 기존 설정을 쓰려면 이전 실행 폴더의 config.toml을 복사합니다.

## output_ 생성 용량 제한 (1.0.1.7)

환경설정의 **모바일 출력 → 기준 용량 이상의 출력 파일 생성 제외**를 켜고 MB 기준을 입력합니다. 기본 해제/500 MB, 정수 1..1000000 MB이며 1 MB=1,000,000 bytes입니다. 사진과 영상 모두 임시 변환 결과가 기준과 같거나 크면 최종 output_ 파일을 저장하지 않습니다. 기준 미만이면 저장하고 촬영 시각을 적용합니다.

일반 분류 폴더의 copy/move는 기존대로 진행합니다. 기존 output_ 파일은 용량 제외 시 삭제하거나 교체하지 않습니다. 실행 결과와 로그에 출력 용량 제한 제외 및 결과 크기/기준을 기록하며 다음 파일을 계속 처리합니다. 변환 후 크기 판정이므로 임시 공간과 변환 시간은 필요하고 미리보기에서는 제외 여부가 확정되지 않습니다. 영상의 ‘원본보다 작을 때만 생성’ 조건으로 먼저 건너뛰는 경우 기존 건너뜀 결과를 유지합니다.

설정 키는 mobile_output_limit_enabled / mobile_output_limit_mb입니다. 휴대폰 전송 단계의 동영상 용량 제한과 독립입니다.

## 동영상 품질 프로필 6단계 (1.0.1.8)

환경설정 → 동영상 출력 → 품질 프로필에서 이름과 CRF·오디오 kbps를 함께 확인합니다. 선택한 프로필 설명이 바로 아래에 표시됩니다.

| 품질 | CRF | 오디오 kbps | 저장 키 |
|---|---:|---:|---|
| 매우 높음 | 18 | 192 | very_high |
| 높음+ | 20 | 192 | high_plus |
| 높음 | 22 | 160 | high |
| 균형 (기본) | 24 | 128 | balanced |
| 용량 절약 | 26 | 128 | compact |
| 최대 용량 절약 | 28 | 96 | small |

낮은 CRF는 화질을 우선하며 용량이 커지는 경향이 있습니다. 결과 크기는 길이·장면에 따라 달라지고 고정 감소율은 보장하지 않습니다. 최대 가로 크기는 별도 설정이며 인코딩 속도 medium은 유지합니다. 이전 높음/균형/작게 설정의 실제 값은 유지됩니다. 기존 small은 최대 용량 절약으로 표시됩니다. 잘못된 품질 설정은 균형으로 정규화합니다.

## 작업 저장·열기와 최근 작업 복구 (1.0.1.9)

화면 상단의 `새 작업`, `작업 열기`, `작업 저장`, `다른 이름으로 저장`을 사용한다. 작업 파일은 `*.pojob.json`이며 Source/Target, 처리 설정, 모델 선택, 수정한 파일명, 미리보기와 실행 결과, 선택한 탭을 보관한다. 사진·영상 원본 자체는 포함하지 않는다. `*`는 이름 있는 작업 파일에 저장하지 않은 변경을 뜻하며 최근 자동 복구 저장과는 별개다. 다른 이름으로 저장하면 별도 작업 ID를 사용하고 이전 작업 파일은 유지한다.

- 환경설정 → 작업 저장·복원에서 `시작할 때 마지막 작업 복원`, `작업 변경 자동 복구 저장`을 선택한다. 둘 다 기본 사용이다. 자동 복구 파일은 실행 폴더의 `sessions/last_session.pojob.json`이다. 설정을 끈 경우에도 실행 시작·종료 기록은 안전을 위해 저장한다. 시작 기록 저장 실패 시 파일 처리를 시작하지 않는다.
- 실행 전 저장한 미리보기를 열면 원본의 존재·크기·수정 시각과 대상 경로를 확인한다. 원본 변경이나 기존 대상/출력 파일 충돌이 있으면 실행을 막고 새 미리보기를 요구한다. 이 파일 상태 값은 촬영 날짜 판단에 사용하지 않는다. 분류 경로에 영향을 주는 설정을 바꾼 뒤에는 저장하기 전에 미리보기를 갱신해야 한다.
- 실행을 시작한 작업은 미리보기·일반 실행·처리 설정 변경을 잠근다. 1.0.1.10부터 검증된 미처리·실패 단계는 아래 복구 버튼으로 처리한다. 새 처리는 `새 작업`에서 시작한다.
- 복원 화면의 성공·오류는 과거 실행 기록이다. 현재 결과 파일의 누락·변경은 별도 상태와 경로 툴팁으로 표시한다. 모바일 복사는 현재 Target의 실제 `output_` 폴더를 검색하므로 과거 결과와 대상이 다를 수 있다.
- 작업을 열어도 앱의 기본 처리 설정을 덮어쓰지 않는다. 환경설정의 `기본 설정에도 저장`을 직접 선택하면 기본값에 반영한다. 실행 시작 후에도 휴대폰 충돌 정책·전송 제한과 앱 복원 설정은 변경할 수 있다.
- 새 작업/열기/종료 시 미저장 변경은 저장·버리기·취소로 확인한다. 실행 중 작업 전환과 종료는 차단한다. 불러온 삭제 리뷰는 모두 체크 해제하며 삭제 직전 원본과 정리 결과 파일을 재검증한다.

작업 JSON은 스키마·단계·경로를 검증하며 손상되었거나 지원하지 않는 파일을 열면 현재 작업을 유지한다. 최대 128 MiB, 목록별 100,000개이며 임시 파일 저장 후 교체하여 저장 실패 시 이전 파일을 보존한다. 상세 설계: `docs/superpowers/specs/2026-10-11-job-save-open-design.md`.

## 작업 복구 2차 설계 (구현 전)

## 중단 이어하기·실패 단계 재시도 (1.0.1.10)

작업을 열거나 최근 작업을 복원한 뒤 `이어서 실행`은 미처리 단계를, `실패 항목 재시도`는 실패 단계를 선택한다. 먼저 복구 계획 창에서 파일별 일반 정리·output 생성·이동 원본 제거의 완료 유지/실행/선행 단계 대기/확인 필요 사유를 확인하고 가능한 항목을 실행한다. 선행 단계가 성공한 경우에만 뒤의 대기 단계를 진행한다.

- 일반 정리가 완료되고 output만 실패했다면 검증된 Target 파일로 output만 다시 만든다. 완료한 일반 파일은 재복사하지 않는다. 출력 건너뜀·용량 제외는 정상 종료로 유지한다.
- 새 저널 방식의 이동은 일반 정리와 output 정상 종료를 기록한 뒤 원본을 제거한다. output 실패 시 원본이 남는다. 기존 비저널 엔진 호출에는 이 정책을 소급 적용하지 않는다.
- 원본 변경, 완료 파일 변경·누락, 기존 대상 충돌, 완료 여부가 불확실한 중단 단계는 자동 처리하지 않고 파일을 보존한다. 복구는 기존 파일을 덮어쓰지 않는다. 안전한 다른 항목은 계속 처리할 수 있다.
- 실행 폴더 `sessions/execution_journal.sqlite`가 실행 진행의 기준이다. JSON schema2에는 계획/단계 스냅샷을 저장한다. 오래된 실행 전 저장본도 같은 계획의 DB 기록이 있으면 최신 진행으로 복원한다. 다른 이름으로 저장해도 처리 계획·실행 ID는 유지하여 중복 실행을 막는다.
- 작업 JSON만 다른 PC나 새 배포 폴더로 옮기면 실행 시작 작업은 조회만 가능하다. 기존 작업을 이어가려면 앱을 모두 종료한 상태에서 같은 실행 폴더의 `sessions` 전체를 보존한다. 구형 schema1의 이미 실행한 작업은 단계 증거가 없어 조회만 가능하고 실행 전 작업은 새 기록 방식으로 실행할 수 있다.
- 새 버전의 미디어 실행은 Windows 공통 잠금으로 배포 폴더 간 동시 실행을 막는다. 이전 버전 프로그램과 외부 파일 변경은 이 잠금에 참여하지 않으므로 각 단계에서 경로·파일 상태를 다시 확인한다. FFmpeg 영상 내부 지점 재개와 휴대폰 전송 재개는 포함하지 않는다.
