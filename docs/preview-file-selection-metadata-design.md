# 미리보기 개별 제외와 원본 모델명 수정 설계안

상태: 사용자 승인 후 선택 코어·원본 기록 서비스·UI·도구 동봉을 구현하고 전체 회귀·GUI 렌더·EXE 검증을 완료했다.
날짜: 2026-10-13. 릴리스 대상1.0.1.26이며 배포 검증 완료는 별도로 기록한다.

## 요구사항

미리보기에서 문제가 있는 파일을 개별 제외하거나, 원본 파일에 모델명을 직접 기록하여 메타정보 부재를 해소한다. 사용자는 작업 전용 이름 변경 대신 원본 메타정보 수정을 명시했다. 첫 수정 항목은 모델명이며 촬영 일시 등 다른 항목을 일괄 변경하지 않는다.

## 개별 처리 선택

- 미리보기 맨 앞에 `처리` 체크박스를 표시한다. 기본은 포함이며 우클릭 메뉴에서 선택한 여러 행을 제외/다시 포함할 수 있다.
- 최종 포함 여부는 모델 선택과 파일 선택의 교집합이다. 모델을 해제했다가 다시 선택해도 개별 제외는 유지한다. 두 선택 상태를 별도로 저장한다.
- 제외한 행은 유지하고 제외 사유를 표시하며 일반 Target 정리, output_ 생성, 이동 모드의 원본 제거 대상에서 모두 제외한다. 개별 제외와 UNKNOWN 표시를 구분한다.
- 기존 촬영 일시/경로 기준 순서를 유지해 포함 항목의 날짜별 SEQ와 예상 경로를 다시 계산한다. 사용자가 편집한 파일명은 유지하고 이름 충돌을 표시한다.
- 실행 시작 후에는 처리 계획을 고정한다. 미리보기/변환/원본 수정 중에는 선택 변경을 잠그되 파일 조회는 허용한다.
- 작업 저장/자동 저장/로드에서 개별 선택을 보존한다. 기존 작업에는 기본 포함 상태를 적용하고 기존 모델 제외 상태를 보존한다. 컬럼 배치도 기존 폭/순서를 유지해 새 열을 추가한다.
- 구현에서는 기존 미리보기 논리0~8열을 보존하고 `처리` 열을 논리9로 추가해 기본 시각 순서만 맨 앞으로 둔다. `file_selected`와 `selected_models`는 독립 저장하며 최종 `included`는 교집합이다. 구작업의 기존 계획 서명은 기본값일 때 보존하고 새 개별 제외 상태는 불변 계획 검증에 포함한다.
- 모델 수정으로 새로운 모델이 나타나면 해당 모델 필터는 기본 선택하고 기존 모델의 선택 상태를 유지한다. 파일별 제외 상태는 변경하지 않는다.

## 원본 모델명 수정

- 선택한 한 행의 우클릭 메뉴와 상세 영역에 `원본 메타정보 수정`을 제공한다. 제외된 행도 실행 전에는 수정할 수 있다.
- 편집창에 확장자가 포함된 원본 경로, 실제 모델 태그와 추론/매핑 모델을 따로 표시한다. 다른 파일의 실제 모델명을 입력 후보로 제공하되 UNKNOWN이나 출력 별칭을 자동 기록하지 않는다.
- 사용자가 모델명을 입력하면 변경 전/후 값과 백업 위치를 보여주고 `원본에 저장`으로 적용한다. 이번 단계는 모델명만 지원하고 촬영 일시/GPS/인코더/코덱은 읽기 전용이다.
- 적용 전에 원본 상태, 쓰기 가능 여부, 저장 공간, 수정 지원 형식을 확인한다. 실행 시작된 작업의 원본 수정은 거절하며 새 미리보기 작업으로 진행한다.
- 같은 볼륨의 임시 복사본에 명시적인 모델 태그만 기록한다. 영상/사진 재인코딩 없이 기록하고 원본 시각, 방향, GPS, 해상도, 영상/음성 스트림 등 변경하지 않을 항목을 확인한다.
- 앱의 실제 메타정보 읽기 경로에서 입력 모델명이 확인되는지 검증한다. 수정 전 원본 전체를 별도 백업으로 복사·flush·검증하고 원본을 그 자리에 유지한 채 수정본을 원자 교체한다. 백업 이름 충돌 시 기존 백업을 덮어쓰지 않는다. 실패 시 기존 파일을 유지/복원하고 백업을 자동 삭제하지 않는다.
- 백업·임시본·원본 수정 저널은 Source 파일과 같은 볼륨의 앱 소유 메타수정 보관 폴더에 저장한다. 소유 표식이 없는 기존 폴더를 재사용하지 않는다. 앱 소유 보관 폴더는 미리보기·추론·모바일 복사 스캔에서 제외한다. 임시본만 정상 파일 확장자를 사용하고 백업/기록은 미디어 확장자를 사용하지 않는다.
- 교체 전 저널을 원자 저장·flush하고 원본/백업/수정본의 내용 지문을 기록한다. 재시작 후에도 원본 메타정보 조회 시 미완료 교체를 확인한다. 원본이 수정 전 지문이면 원본을 유지하고, 수정 후 지문이면 조회 결과에 완료 상태를 표시한다. 어느 쪽도 아니면 자동 덮어쓰기 없이 백업과 기록을 보존하고 복원을 거절한다. 이는 중복 파일 비교가 아닌 단일 원본 변경의 복구 검증이다.
- 수정 전 원본 전체의 백업 파일과 변경 기록을 보존한다. 프로그램 내 `백업으로 복원`은 크기/시각뿐 아니라 수정 후 내용 지문까지 비교해 현재 파일이 외부에서 바뀌지 않았는지 확인하고 변경 전/후 정보를 보여준 뒤 수행한다.
- 수정된 원본을 다시 읽고 같은 폴더의 영상 추론, 전체 이름/분류 폴더/날짜별 SEQ/오류 예상과 원본 지문을 갱신한다. 수동 파일명과 개별 제외는 보존한다. 원본 기록은 성공했지만 재계획이 실패하면 성공 기록을 보존하고 실행을 막아 재미리보기를 안내한다.
- 이미지/메타정보 캐시를 무효화하고 작업을 변경 상태로 표시한다. 작업 저장은 편집창이나 원본 수정 중간 상태를 실행 가능한 계획으로 저장하지 않는다.
- 쓰기/복원 전 `metadata_refresh_required=True` 상태를 최근 작업과 현재 열린 작업 파일에 강제로 checkpoint한다. 이 저장에 실패하면 원본을 수정하지 않는다. 일반 자동저장 해제도 이 안전 저장을 생략하지 않는다. 성공 재계획 후 새 원본 기준값과 미리보기를 checkpoint한다. 재계획 또는 완료 checkpoint가 실패하면 이전 미리보기를 보존하되 저장/로드 후에도 새 미리보기 전까지 실행 등록과 preflight를 차단한다. 실행 시작 작업과 재계획 대기 플래그 참의 조합은 허용하지 않는다.

## 기록 도구와 형식

설계 당시 ExifTool은 PATH에서 발견되지 않았다. 사용자 승인 후 공식 Windows x64 ExifTool13.59를 프로젝트 전용 도구로 동봉했다. 시스템 PATH나 전역 설치를 바꾸지 않는다. 공식 ZIP SHA256·전체 파일 manifest·출처·원본 라이선스를 고정하고 `scripts/vendor_exiftool.py`의 설치/오프라인 검증 및 빌드 전 검증을 사용한다. 설치는 기존 파일을 덮어쓰지 않는다. 자세한 내용은 `tools/exiftool/VENDOR.md`에 기록한다.

ExifTool 공식 형식표는 JPEG/PNG/HEIC/MOV/MP4 쓰기를 지원하고 AVI/MKV/WMV는 읽기 전용이다. 앱의 현재 수정 활성화 형식은 JPG/JPEG/PNG/MP4/MOV/M4V이며 수정본의 모델 태그 재읽기와 보존 검증을 통과해야 교체한다. HEIC는 대표 왕복 검증 전까지 쓰기를 활성화하지 않는다. AVI/MKV/WMV도 미지원 안내를 표시한다. 도구의 일반 쓰기 지원과 앱의 검증된 수정 범위를 구분한다.

사진은 실제 EXIF Model, 영상은 읽기 가능한 명시적 QuickTime 모델 태그를 사용한다. 같은 의미의 기존 모델 태그가 여럿 있으면 충돌한 값을 남기지 않도록 위치별로 확인한다. 기존 ffprobe/MediaInfo/사진 추출 순서를 유지하며 필요한 형식에는 ExifTool 모델 태그 읽기를 보완한다.

외부 의존성 변경은 AGENT.md11항에 따라 사용자 승인을 받았다. 사용자 원본 샘플은 테스트에서 수정하지 않고 작업 폴더의 합성/복사 샘플만 사용한다.

## 대안과 추천

1. 작업 전용 수정은 원본 메타정보 부재를 해결하지 못해 사용자 선택과 맞지 않는다.
2. 기존 라이브러리로 JPEG만 수정하면 사진/영상의 공통 흐름을 제공하기 어렵다.
3. 사용자 승인으로 ExifTool 동봉과 원본 백업·검증 후 교체 방식을 채택했다. 배포 용량과 임시/백업 공간이 늘지만 모델명 기록을 형식별로 명확하게 검증할 수 있다.

## 구현 및 검증 순서

1. 개별 선택 상태와 모델 필터 교집합, 재계획·작업 저장·불변 계획 검증을 분리 구현한다.
2. 원본 기록 서비스, 형식별 capability, 백업/교체/복원/지문 확인을 UI와 분리 구현한다.
3. 편집창·원본 재읽기·메타정보 캐시·재미리보기·작업 저장 통합을 구현한다.
4. 파일 제외 후 모델 토글·SEQ·수동 이름·기존 열 배치·로드/실행을 회귀 검증한다.
5. 실제 JPEG/PNG/MP4 합성 샘플 왕복, 지원 형식 fixture, 태그 충돌, 기존 태그/미디어 보존, 실패/취소/동일크기·시각 원본 외부 변경·백업 복원·재계획 실패·백업 스캔 제외·강제 종료 후 저널 복구를 검증한다. HEIC/MOV/M4V는 대표 샘플 검증을 완료한 형식만 활성화한다.
6. 문서는1.0.1.26(2026-10-13) 구현 상태로 현행화했다. 최종 독립 검토·전체755개 회귀·1204×1032 GUI 렌더 및 EXE 빌드/내장 도구 실행 검증은 VALIDATION에 기록했다. origin에는 별도 요청 없이 반영하지 않는다.
