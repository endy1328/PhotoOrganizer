# 모바일 복사 상대 경로 유지 설계 및 구현 계획

**목표:** 사용자가 휴대폰의 Photo 같은 기준 위치를 한 번 선택하면 Target 기준 목록의 연도/월/날짜/모델/output_ 상대 경로를 그대로 유지해 전송한다.
**승인:** 2026-10-13 대화에서 전체 경로 유지·기존 폴더 합치기를 확인하고 사용자가 구현을 요청했다.
**구조:** 스캔 시 출력 폴더에 불변 상대 경로 구성요소를 기록한다. 크기 필터와 미전송 재시도도 경로를 보존한다. 전송은 선택한 휴대폰 객체 아래부터 각 경로 요소를 재사용하거나 생성한다. UI와 코어는 같은 경로 계산 함수를 사용한다.
**환경:** 기존 Python/PySide6/WPD와 메모리 기기 테스트를 사용하며 외부 의존성을 추가하지 않는다. 현재 checkout의 기존 변경은 유지하고 Git origin 반영은 하지 않는다.

## 확정 정책

- Target의 상대 경로 전체를 선택한 휴대폰 위치 아래에 붙인다. Target 이름 자체는 붙이지 않는다. 표시 경로가 `2024년/2024년 10월/20241006/20241006_GalaxyZFold6/output_20241006_GalaxyZFold6`이면 Photo 아래에 그 구조가 생긴다.
- 같은 이름의 유일한 폴더는 재사용하고 없는 폴더만 생성한다. 경로에 파일 또는 동명 폴더 여러 개가 있으면 해당 항목을 실패 처리한다. 다른 경로로 임의 우회하거나 기존 폴더를 지우지 않는다.
- 전송 대상은 선택한 output_ 폴더 및 내용뿐이다. 상위 폴더의 다른 PC 원본은 보내지 않는다. 기존 휴대폰의 다른 파일/폴더는 보존한다. 같은 파일명 처리는 현재 환경설정(기본 덮어쓰기/건너뛰기/새 이름)을 그대로 따른다.
- 여러 연/월을 한 번에 보낼 수 있으며 다른 상위 상대 경로에 있는 동명 output_도 허용한다. 실제 전체 상대 경로가 휴대폰 이름 비교 기준으로 겹치면 거부한다.
- 상대 경로를 스캔 시 고정한다. 빈 값/절대경로/상위 경로 탈출/구분자 포함 요소는 거부하며 전송/재시도 전 검증한다. 기존 직접 만든 OutputFolder의 기본 경로는 예전 standalone API와 호환하지만 실제 UI 스캔은 전체 경로를 사용한다.
- 휴대폰에서 Photo 같은 복사 루트를 선택하도록 텍스트로 안내한다. 이미 월/연도 폴더를 선택한 경우 자동으로 경로를 생략하지 않는다. 목록의 전체 경로와 실제 휴대폰 예정 경로를 툴팁으로 확인할 수 있다. 저장 경로 북마크는 기존대로 유지한다.
- 기존 모델/파일 선택·영상 용량 제한·진행률·취소·안전 덮어쓰기·실패 재시도 정책은 유지한다.
