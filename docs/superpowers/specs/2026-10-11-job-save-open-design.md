# 작업 저장·열기 설계

상태: 사용자 승인 후 1.0.1.9에 1차 구현·회귀·배포 빌드 완료. 항목별 부분 재시도는2차 범위로 유지한다.

## 1. 목적과 선택안

미리보기 또는 실행 결과를 작업 파일로 저장하고 프로그램을 다시 실행한 뒤 원하는 작업을 열어 이어서 사용한다. 사진·영상 자체는 작업 파일에 포함하지 않는다.

세 가지 방식 중 이름 있는 작업 파일과 최근 작업 복구를 함께 사용하는 안을 추천한다.

| 방식 | 장점 | 한계 |
|---|---|---|
| 최근 작업만 자동 복원 | 간단함 | 여러 작업 보관/선택 어려움 |
| 작업 파일 수동 저장·열기 | 작업별 보관과 이동 가능 | 저장을 잊으면 변경 누락 |
| 작업 파일 + 최근 복구 파일 | 작업 관리와 최근 상태 복구 가능 | 저장 상태/UI 구분 필요 |

## 2. 1차 범위

- 새 작업, 작업 열기, 작업 저장, 다른 이름으로 저장.
- 미리보기 저장·복원: 경로, 작업 설정, 모델 선택, 수동 파일명, SEQ, 메타데이터 표시, 예상 오류.
- 실행 결과 저장·복원: 성공/오류/의도된 출력 제외/결과가 없는 미처리 항목, 실제 생성 경로, 삭제 리뷰 후보.
- 최근 작업 자동 저장과 시작 시 복원 선택. 기본은 마지막 작업 자동 복원 켜짐. 복원은 화면 표시만 하며 실행/모바일 전송/삭제를 시작하지 않는다.
- 미리보기 작업은 재검증 후 실행 가능. 실행을 시작한 작업은 결과 조회/모바일 복사용이며 일반 실행을 잠근다.

1차에서 제공하지 않는 기능: 실패 항목만 재변환, 강제 종료된 파일의 자동 이어하기, 작업 파일에 원본 포함, 경로 재연결 마법사, 휴대폰 전송 큐 복원.

## 3. UI

현재 작업 버튼 영역 위에 새 작업 / 작업 열기 / 작업 저장 / 다른 이름으로 저장 행을 둔다. 상태에는 작업 이름, 단계, 저장하지 않은 변경(*)을 표시한다.

- 새 작업: 현재 기본 환경설정으로 목록 없는 새 작업 생성. 기존 Source/Target 입력을 초기값으로 유지할 수 있으나 결과는 비운다.
- 열기: 파일 선택 후 읽기/검증이 모두 성공해야 현재 화면 교체. 실패하면 기존 작업과 선택을 유지한다.
- 저장: 처음이면 경로 선택, 이후 같은 파일 저장. 다른 이름으로 저장은 새 job_id로 독립 작업 사본 생성.
- 저장하지 않은 변경이 있을 때 새 작업/열기/종료: 저장/저장하지 않음/취소. 자동 복구 파일이 있더라도 명시적인 작업 파일 저장 여부는 별도로 관리한다.
- 실행 중에는 작업 전환/저장/종료를 차단한다. 현재 동기 엔진의 processEvents 재진입으로 실행 중 닫기가 처리되는 문제를 함께 막는다.
- 미리보기 작업: 모델 선택/새 파일명 수정 가능. 실행 단계 이후: 목록/수동명은 읽기 전용, 실행 버튼 비활성화.
- 완료된 작업을 다시 정리하려면 새 작업에서 미리보기한다. 기존 결과를 암묵적으로 초기화하지 않는다.

## 4. 파일 형식

확장자: *.pojob.json (예: 2024년_5월_정리.pojob.json). UTF-8 JSON, schema_version=1.

저장 내용:
- format='PhotoOrganizerJob', schema_version, app_version, job_id, revision, saved_at_utc.
- phase: DRAFT / PREVIEW_READY / EXECUTING / EXECUTION_FINISHED / EXECUTION_PARTIAL.
- PREVIEW_READY는 실행 시작 기록/실행 결과가 없는 미리보기만 해당한다. EXECUTION_FINISHED는 포함 항목 모두에 결과가 있는 상태이며 개별 오류는 있을 수 있다. EXECUTION_PARTIAL은 실행 반환 후 결과 없는 포함 항목이 남은 상태, EXECUTING은 반환 기록이 없어 완료 여부가 불확실한 상태다.
- 작업 설정 스냅샷: Source/Target, copy/move, 모델 매핑/추론, 사진/영상 출력 품질과 용량 제한, 모바일 복사 정책.
- 미리보기 항목과 포함 여부/수동명, 원본 미디어의 날짜/모델/출처 등 재계획에 필요한 최소 정보.
- 실행 결과, 오류, 삭제 리뷰 후보, 표시 로그, 마지막 탭.
- 경로별 확인 정보: 존재 여부, 일반 파일 여부, 크기, mtime_ns. 이동 결과는 원본과 Target 상태를 별도로 기록한다.

원본 확인 기준값은 미리보기 당시 고정한다. 저장/열기 시 현재 값으로 덮어써 변경을 정상 상태로 인정하지 않는다. 정리/출력 결과 확인 기준값은 해당 실행 완료 시점에 별도로 기록하며 현재 조회 상태와 분리한다.

Path/촬영 datetime은 명시적 문자열로 변환한다. EXIF 라이브러리 객체 등 임의 raw metadata는 직렬화하지 않고 표시용 문자열 metadata_entries와 재계획에 필요한 primitive 정보만 저장한다. 촬영 일시는 기존 값을 그대로 보존하며 파일 시스템 시간으로 대체하지 않는다.

schema_version과 앱 버전은 분리한다. 스키마1의 새 선택 필드는 기본값을 명시하되 필수 항목은 누락 시 거부한다. 미래 스키마는 열기 거부, 구스키마는 명시적인 변환 규칙만 적용한다.

## 5. 작업 설정과 기본 설정

작업 열기는 저장된 설정을 현재 작업에만 적용한다. config.toml을 자동으로 덮어쓰지 않는다. 환경설정에 기본설정에도 저장 선택을 두고 열린 작업에서는 기본 해제로 한다. 새 작업은 기본 설정을 가져온다.

최근 자동 복원/일반 변경 자동 저장 사용 여부는 앱 기본 설정이며 개별 작업의 처리 설정에서 제외한다. 둘 다 기본 켜짐이며 아래 실행 시작/반환 안전 체크포인트는 이 옵션과 독립적으로 필수다. 작업 열기/종료 때 현재의 _save_current_inputs가 작업 설정을 전역 설정으로 저장하는 경로도 수정해야 한다.

## 6. 저장과 최근 복구

- 같은 폴더의 임시 파일 쓰기 → flush/fsync → os.replace. 실패 시 기존 파일 유지/임시 정리. 성공 후에만 저장 완료 표시.
- 명시 작업 파일은 작업 저장 동작으로만 갱신한다. 최근 복구는 실행 폴더 sessions/last_session.pojob.json 1개로 별도 관리한다.
- 자동 저장 시점: 미리보기 완료, 모델 선택/수동명/설정 변경의 짧은 debounce, 실행 시작 직전, 실행 반환 후.
- 실행 시작 직전 EXECUTING 상태를 복구 파일에 기록한다. 이 기록을 저장하지 못하면 실행을 시작하지 않고 저장 문제를 안내한다. 실행 중 파일별 완료 기록은 2차 범위다.
- 실행 시작/반환 체크포인트는 일반 변경 자동 저장을 꺼도 유지한다. 시작 시 자동 복원 해제는 자동으로 화면을 여는 기능만 끄며 저장된 복구 파일은 수동으로 열 수 있다.
- 완료 후 자동 저장 실패는 이미 완료한 파일 작업을 실패로 바꾸지 않는다. 상태에 실패를 알리고 수동 저장 가능하게 한다.
- 시작 시 기본 설정이 허용하면 최근 복구 파일을 자동으로 연다. 손상/미지원이면 빈 작업으로 시작하고 사유 표시. 연결되지 않은 경로가 있어도 과거 결과는 조회 가능하다.
- 명시 저장의 변경 여부와 복구 저장 여부를 따로 관리한다. 마지막 명시 작업 경로는 참고로 저장하되 복구 파일에서 자동으로 그 파일을 덮어쓰지 않는다.

## 7. 열기와 실행 재검증

열기는 미디어 수정/Target 생성/휴대폰 연결/삭제를 수행하지 않는다. 로드 크기 상한128MiB와 총 미리보기 항목100000개, 필수 타입/enum/중복 item_id/경로/확장자/수동명/모델 매핑을 검증한다. 저장도 같은 상한을 검사하여 저장 불가능한 크기는 기존 파일을 보존한 채 안내한다.

저장된 대상 경로는 Target 루트 안에 있어야 하며 촬영 날짜/모델 폴더/새 파일명으로 계산되는 예상 경로와 일치해야 한다. output_ 경로도 동일한 계산 규칙을 검증한다. Source 밖 파일, 링크/정션 경로, 임의 삭제 후보를 실행 대상으로 신뢰하지 않는다.

PREVIEW_READY는 열기 후와 실행 직전에 원본 크기/mtime_ns 및 경로 상태를 확인한다. 변경/누락은 재미리보기가 필요하다. 불러온 미리보기의 Target/output_ 경로가 이미 존재하면 저장된 OVERWRITE 표시를 신뢰하지 않고 충돌로 차단한다. 저장된 이름/SEQ는 자동 변경하지 않는다. 재검증 실패 시 전체 실행을 차단하며 문제 목록을 표시한다.

크기/mtime 비교는 변경 감지용이며 내용 동일성 보증이 아니다. 파일 해시/중복 이미지 비교는 이번 범위에 추가하지 않는다.

EXECUTING / EXECUTION_FINISHED / EXECUTION_PARTIAL은 일반 실행을 차단한다. EXECUTING은 중단 여부/완료 여부 미확인으로 표시한다. 결과가 없는 포함 항목은 미처리 또는 확인 불가로 구분하고 성공으로 추정하지 않는다.

단계와 기록이 모순되는 파일(예: PREVIEW_READY에 실행 시작 기록이나 결과가 있음)은 열기를 거부한다. PREVIEW_READY로 단계를 바꾸는 것으로 결과 작업이 실행 가능한 상태가 되어서는 안 된다.

실행 결과의 과거 성공과 현재 파일 상태를 분리해 표시한다. 이동 완료 작업에서 원본 없음은 정상일 수 있다. 모바일 복사는 기존처럼 현재 Target의 실제 output_ 파일을 조회한다. 과거 SIZE_EXCLUDED라도 이전 실행에서 생성된 output_ 파일이 남아 있으면 조회 대상에 포함될 수 있음을 표시한다. 이번 설계는 특정 실행에서 생성한 파일만 전송하는 정책으로 변경하지 않는다.

삭제 리뷰는 체크를 모두 해제한다. 삭제 실행 전 현재 원본이 미리보기 기준값과 일치하고 정리 결과 파일이 실행 완료 당시 기준값과 일치하는지 다시 확인한다. 이상이면 해당 삭제를 차단한다. 자동 삭제는 없다.

## 8. 2차 재시도 설계의 전제

현재 전체 ERROR는 일반 파일 정리가 실패했거나 정리 후 모바일 출력만 실패한 두 경우를 포함한다. 이동 작업에서는 ERROR여도 원본이 이미 Target으로 이동했을 수 있다.

재시도를 지원하려면 항목별 main 정리 상태 / 모바일 출력 상태 / 원본 제거 상태, 실행 전후 의도/완료 저널을 별도로 기록해야 한다. 성공 main을 다시 실행하지 않고 필요한 모바일 출력만 생성할 수 있어야 한다. 불확실한 완료/부분 파일은 확인 또는 새 경로가 필요하다. SIZE_EXCLUDED/SKIPPED는 의도된 제외이며 실패 재시도 대상이 아니다. 파일별 재개는 별도 승인/구현 단위로 진행한다.

## 9. 구현 구분과 검증 계획

- job_store.py: JSON 스키마/명시적 모델 변환/원자 저장/로드 검증, Qt 독립.
- job_validation.py: 저장된 경로 규칙/원본 변경/Target 충돌/삭제 후보 검사.
- models.py: 앱 전역 복원·자동 저장 설정. 작업 단계/스냅샷 모델은 job_store.JobState에 둔다.
- main_window.py: 작업 버튼/작업 전용 설정/dirty/자동 저장/복원/단계별 잠금.
- config.py: 앱의 최근 복원 기본값과 작업 설정 분리.
- ui/job_controller.py: 엔진 호출 전후 체크포인트와 저장본 실행 전 검증을 담당한다. 엔진의 기존 정리 규칙을 유지한다.

테스트: 전체 상태 roundtrip, Unicode/모델 선택/수동명/매핑/SEQ/품질/생성·전송 제한, 이전·미래스키마/손상 JSON, 저장 중 실패, 경로 조작/링크/대상 충돌, 이동 원본 부재/모바일 실패/미처리, 제외 결과, 기존 결과 재실행 차단, 설정 분리/종료 차단, 삭제 체크 해제, 복원 후 모바일 조회. 전체 회귀 및 독립 검토 후 구현 릴리스 버전 갱신/EXE 빌드.

## 10. 검토 결과

저장/UI/재실행 관점의 판단 에이전트3개를 병렬 검토했다. 공통 결론은 작업 설정 스냅샷 분리와 실행 결과 재실행 잠금이다. 최근 복원은 자동/제안 의견이 나뉘었으며 원래 재실행 시 이전 화면 복원 요구에 맞춰 기본 자동 복원을 채택했다. 외부 파일 작업은 시작하지 않는다.
