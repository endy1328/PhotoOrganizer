# GPU와 사진 병렬 변환 / 1.0.1.13

상태: 사용자 승인 후 구현 완료. 최종480개 회귀(478통과/2skip), 실제 성능 비교·GUI·1.0.1.13 EXE 검증 완료.

## 범위

- 영상 처리 방식 auto/cpu/gpu, 변환 속도 quality/balanced/fast, 사진 동시 처리 수1/2/4를 환경설정에 추가한다. 새 작업 기본 auto/balanced/2. 영상은 동시에 하나만 처리한다.
- auto는 실제 NVENC 인코딩 가능 여부를 짧은 무창 테스트로 확인하며 미지원/실패 시 CPU로 전환한다. GPU 지정은 불가 사유를 표시한다. 기존6단계 품질을 유지하지만 CPU CRF와 GPU CQ가 같은 화질/용량이라는 보장은 하지 않는다.
- CPU 속도 slow/medium/fast, NVENC p7/p5/p3. 큰 사진 축소는 reducing_gap 최적화를 적용하고 빠름에서 저장 압축 최적화 비용을 줄인다. 화질/메타정보/촬영일·크기 제한 정책을 보존한다.

## SEQ 및 안전성

- 촬영 시각/경로 정렬과 날짜별 사진·영상·모델·UNKNOWN 공통 SEQ는 미리보기에서만 배정한다. worker는 확정 경로를 사용하며 완료 순서로 번호를 부여하지 않는다. 결과 표시와 저널 복구도 고정 계획 순서를 사용한다.
- 제출 수는 동시 처리 수로 제한한다. 멈춤 요청 후 새 파일을 시작하지 않으며 이미 시작한 파일의 정리·출력·이동 제거·완료 기록을 마친 뒤 대기/중단한다. 아직 시작하지 않은 파일은 PENDING으로 유지한다.
- SQLite 기록과 공유 작업 상태 변경은 직렬화한다. 완료 전 게시 의도와 완료 증거를 기록하며 파일별 고유 임시 경로 및 NEW 독점 게시를 보존한다. 기록 불확실성이 생기면 이후 변경을 차단한다.
- 강제 종료 뒤 hot rollback journal 복구를 허용하도록 기존 실행 DB만 mode=rw로 연다. 없는 DB를 생성하거나 복원 조회에서 미디어 파일을 변경하지 않는다.
- 기존 저장 작업에 성능 설정이 없으면 CPU/balanced/1로 해석하여 이전 동작과 계획 서명을 유지한다. 새 설정이 들어간 계획은 실행 뒤 변경하지 않는다.

## 검증

설정 저장/잘못된 값/구버전 작업, 실제 NVENC, GPU 불가 및 실패 CPU전환, 기존 FFmpeg 옵션, 사진 출력 메타정보와 크기, 역순 완료 SEQ/결과 순서, 중단·재개·이동·기록 실패를 테스트한다. 대표 영상 성능 수치는 측정한 샘플에 한정하고 GPU 인코딩 가능 확인과 속도 개선 측정을 구분한다. 문서5종·4자리 버전·EXE를 갱신한다.
